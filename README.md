# Clinical Biometrics Mastery OS

**▶ Try it: https://jorgeaistatistics.github.io/biostatsproject/** — runs entirely in the browser, no
sign-up, nothing collected. Your progress is stored in your own browser only.

An interactive training environment for clinical statistical programming, biostatistics, CDISC
standards and applied pharma/biotech analytics — built around synthetic clinical studies that you
follow from protocol to clinical study report.

It is designed to be used continuously alongside an MS in Biostatistics (roughly 5–8 hours a week
for 18–24 months), and to make the work — not just the definitions — familiar: reading messy clinical
data, writing SAS/R/Python/SQL, deriving SDTM and ADaM datasets, programming tables and figures,
QCing another programmer's output, interpreting models, and explaining all of it in an interview.

> **Everything in this repository is synthetic and fictional.** CBX-417, VTX-221 and Halden
> Therapeutics do not exist; no real patient data, sponsor or product is involved. This is an
> educational tool, not a validated system, and nothing here is a regulatory submission.

### Principles

1. **No magic numbers.** Where a number comes from is always explained — `:::number` blocks answer
   "where did this number come from?" inline.
2. **Performance, not clicks.** Reading a lesson marks it read. Skill levels move only when you solve,
   debug, QC, explain and apply.
3. **Standards are labelled.** Every standards statement is marked *official requirement*,
   *industry convention* or *educational simplification*.
4. **No fake execution.** SAS cannot run in a browser, and this app never pretends otherwise: SAS
   exercises use syntax-aware structural checks, expected output computed independently, and
   downloadable `.sas` programs. SQL and (optionally) Python really do run.
5. **Verified statistics.** The in-browser statistics engine (Kaplan–Meier, log-rank, Cox with
   Breslow/Efron ties, OLS diagnostics, logistic regression, PCA, exact CIs) is unit-tested against R
   — see `src/lib/stats/stats.test.ts` and `src/lib/tlf/study.test.ts`.

## Running it locally

Requirements: **Node.js 20+** (developed on Node 24) and npm. R and Python are optional and only
needed if you want to re-run the verification scripts or the companion programs.

```bash
npm install
npm run data        # generate the synthetic datasets (writes to data/)
npm run dev         # http://localhost:5173
```

Other scripts:

```bash
npm run build       # typecheck + production build into dist/
npm run preview     # serve the production build
npm run validate    # validate all curriculum content (schemas + cross-references + LaTeX + spreadsheet answers)
npm run test        # unit tests (statistics engine, Excel engine, study numbers)
npm run check       # typecheck + validate + test
npm run capstones   # regenerate the capstone starter folders from content/capstones/capstones.yaml
npm run readme      # regenerate the content table above (--check to verify it in CI)
```

`npm run validate` does more than check schemas. It evaluates every spreadsheet exercise's reference
solution in the same formula engine the app uses and fails if the answer does not match the one the
exercise states, and it runs each `code` item's reference solution against that item's own checks. An
exercise whose stated answer is wrong cannot reach a learner.

`npm run data` regenerates every synthetic study. Where a study has an R script (cardio, oncology and
manufacturing — all skipped gracefully if `Rscript` is absent), it runs afterwards: cardio and oncology
recompute their published `FACTS.md` / `STUDY_FACTS.md` numbers from the generated CSVs, and
manufacturing asserts the properties its documentation claims — that batch summaries are recomputable
from the sensor series, that the messy exports reconcile to `batches.csv`, that the planted excursions
are the size stated, and that row-level cross-validation really is an order of magnitude optimistic. A
change that quietly breaks one of those fails the generator rather than reaching a learner.

The built app is a static site (`dist/`). Serve it with any static server — it needs no backend.
All progress is stored in your browser's local storage and can be exported/imported as JSON from the
Progress page.

Optional in-browser Python (Pyodide, ~25 MB from a CDN) is off by default and can be enabled in
Settings; everything else works offline.

### Curriculum model

- **Skills** (`content/skills/*.yaml`) are grouped into 15 competency domains and tagged on every
  lesson and exercise.
- **Lessons** are markdown with a fixed instructional structure — *What problem are we trying to
  solve? → Intuition → Clinical context → Formal concept → Worked example → Data example → Code →
  Output → Interpretation → Common mistakes → Knowledge check → Hands-on exercise → Challenge →
  Industry note* — plus directives for collapsible explanations, callouts, standards labels,
  line-by-line code annotations, dataset previews, quizzes and interactive widgets.
- **Items** are practice objects in thirteen formats (multiple choice, calculation, mapping,
  ordering, classification, code with structural checks, live SQL, SAS-log review, bug hotspots, QC
  diffs, open interview answers…), each with hints, a solution and, for harder ones, a structured
  explanation.
- See **[CONTENT_GUIDE.md](CONTENT_GUIDE.md)** to add or edit content, and run `npm run validate`.

## Datasets

All datasets are generated deterministically (same seed → identical files) by scripts under
`scripts/data/`, with a `manifest.json` describing every variable (label, type, role, origin,
derivation).

| Study | What it is | Why it exists |
|---|---|---|
| `data/oncology` | **CBX417-301** — randomized, double-blind Phase 2/3-style NSCLC trial: 468 screened, 420 randomized (210/210), 416 treated, data cutoff 2025-03-31. Raw EDC/vendor exports with realistic data problems, 20+ SDTM domains, 8 ADaM datasets, a lineage map from every SDTM record to its raw row, a documented answer key of injected data issues, and a SQLite database. | The spine of the app: SDTM/ADaM labs, TLFs, QC, SQL, survival analysis, capstones. |
| `data/cardio` | **VTX-221** — 12-week, 3-arm antihypertensive trial with repeated SBP measurements and MAR dropout. | ANCOVA, MMRM, missing data, dose-response. |
| `data/teaching` | Tiny fixed datasets (e.g. 12 subjects for Kaplan–Meier by hand). | Hand calculations you can reproduce in SAS, R and Python. |

Data problems injected into the raw layer (duplicates, impossible dates, mixed units, inconsistent
sex coding, partial dates, subjects missing from one source, outliers…) are documented in
`data/oncology/answer-key/` — that folder is the solution key for the data-cleaning capstone.

## Technical architecture

- **Vite + React + TypeScript**, static build, hash routing (works from any static host).
- **Content as data**: YAML/markdown compiled at build time; the UI never hardcodes curriculum.
- **Rendering**: `react-markdown` + remark/rehype with a custom directive plugin; KaTeX for maths;
  CodeMirror 6 grammars for syntax highlighting (SAS, R, Python, SQL) both in editors and in static
  code blocks, so they look identical.
- **Statistics in the browser**: a dependency-free TypeScript implementation (distributions, KM with
  Greenwood variance and log-log intervals, stratified log-rank, Cox PH with Breslow/Efron ties, OLS
  with diagnostics, logistic regression via IRLS, PCA via Jacobi eigen-decomposition, exact binomial
  intervals), validated against R.
- **TLF engine**: tables and figures are computed from the ADaM CSVs at runtime, and every cell keeps
  the records that produced it — which is what makes "Trace this value" possible.
- **SQL**: sql.js (SQLite compiled to WebAssembly) with the study databases bundled; queries run in a
  disposable workspace copy.
- **Spreadsheet sandbox**: a small Excel formula parser/evaluator (SUMIFS, COUNTIFS, XLOOKUP,
  INDEX/MATCH, IF/IFS, text and date functions, Excel serial dates).
- **State**: Zustand with localStorage persistence; no backend, no telemetry, no accounts.

## Limitations (read these)

- **SAS is not executed.** Structural checks verify that your program contains the right constructs;
  they cannot verify that it runs. Use SAS OnDemand for Academics (free for students) or your
  university's SAS to run the `.sas` companions.
- **The data is synthetic.** It is realistic enough to teach with, but it was generated by a model of
  a trial, not by a trial. Real data is messier in ways no generator fully captures.
- **Standards move.** Content targets SDTMIG v3.4 / SDTM v2.0 and ADaMIG v1.3 with controlled
  terminology checked against the NCI EVS CDISC CT. Always confirm against the versions your study
  uses; the app labels official requirements, conventions and simplifications, and links primary
  sources on the Standards & Sources page.
- **Statistical scope.** Mixed models/MMRM and multiple imputation are taught with SAS/R code and
  precomputed output rather than run in the browser.
- **Not a credential.** "Career readiness" is a study aid, not an assessment anyone else recognizes.
